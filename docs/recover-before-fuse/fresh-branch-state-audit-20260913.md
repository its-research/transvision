# 完整序列的已选分支状态重建审计

事件完整 Top-4、逐节点 beam 与恢复开启对照的完整序列状态审计均通过。每组覆盖 train 序列 `0000`
的 195 个事件、7,350 条原始观测；每帧从原始观测重新计算的已选分支状态，与保存的整帧
预测在规范化序列化后逐字节一致。原生 HOTA 下降仍然成立，不能归因于这些运行中
已选分支的缓存状态偏离既定 CI 回放。身份配置本身是否正确是另一项问题。

## 审计对象与方法

入口为 `tools/event_track_v2x/audit_branch_state_replay.py`。它接受一个完整、封存的
car-only train 单序列诊断及指定回执摘要，支持逐节点 beam、整批 beam 和恢复开关后端。
JPDA／PKF 的概率状态更新不属于此工具的 CI 重建合同。CLI 不提供夹具模式。

先复核计划、日程、预测、审计、计时与关闭数据库的摘要，再按事件顺序执行以下检查：

1. 验证预测提交链、审计链、事件时间、状态配置和完整观测计数。
2. 仅加载截至该事件已到达的新增原始观测，核对原始载荷摘要、索引字段和缓存到达回执。
3. 从该事件的追加／重评分记录恢复行势；重评分必须保持原父候选支持。
4. 使用历史深度的分量成员映射与已选前缀祖先链，核对父边支持、源帧互斥、根编号和摘要。
5. 对每个已选分支按状态时刻重做传播与 covariance intersection（CI），独立计算分数、抑制和过期输出。
6. 核对每个已选分支的状态摘要，以及包含全部 ID 的整帧预测；最后再次核对输入和源码摘要。

SQLite 连接只读，授权器拒绝访问持久化状态、权重、最终势表和实时元数据。
历史分量合并后不会用最终 live 标记替代历史成员；未来观测不会加入当前帧重建。
全部观测必须恰好被当前分量覆盖，额外 ID、缺失 ID、漏分量、重复分量均不能通过。

重建复用声明的数值传播、CI 与状态校验原语，但不复用缓存状态、增量状态更新或
状态复制路径。因此，它验证的是「持久化实现是否等价于声明的原始观测回放」，不是
独立数值算法的交叉验证，也不证明 CI 模型在物理世界中正确。

## 资源与失败边界

默认累计上限为 2,000,000 次观测节点访问，逐帧累计全部历史观测数，不按输出框数计数。
该计数不是 CPU 指令数或与在线推断等算力的证据。超限、摘要变化或任一状态不一致时，
停止并记录失败，不发布部分序列通过结论。已有结果目录不覆盖。

审计不读取 GT、不训练模型、不重新选择身份、不回写预测，也不检查未选中的所有分支。
输入原始观测来自封存数据库；本工具不重新运行检测器或独立认证完整数据集来源。
正式运行要求原生产 Python、平台和线程配置，并核对九个状态依赖源码的摘要。
原计划没有单独保存 NumPy／SciPy 版本，审计只记录本次版本，不声称补证了原运行的缺失字段。

## 对论文判断的影响

[完整 Top-4 的原生负结果](reachable-slot-ranking-bound-20260913.md)不变。新的证据排除了
已选分支缓存偏差这一具体解释；不排除状态模型不合适、身份势不合适或决策目标与真实
跟踪质量不一致。也不能把全序列下降归因于最早一个分歧事件。

当前行级训练使用已知选项与全部正确父边之间的 log-sum-exp 差。它不是对完整联合
身份类的全局似然训练。更多搜索得到更高模型权重，不必改善真实身份指标；但仅凭
这种目标形式还不能证明它就是本次下降的原因。下一步应核对真实错误事件中的候选
身份权重、保留集条件决策与标注身份关系，并在相同强后端上分离历史恢复与当前事件
搜索收益，不能直接宣称更换损失或增加网络模块即可解决。

后续[保留身份候选的局部标签诊断](retained-identity-label-diagnostic-20260913.md)已完成
两组完整序列对照。最早分歧事件中，较低局部误差的类仍在 Top-4 内但未被选择；
全序列的既有候选集事后最优仍明显差于逐节点参考。这些是局部标签证据，不是完整
身份真值、原生指标或新时序解码策略的性能上限。

这些结果仍只来自一个已见 train 序列，不是完整 SPD val、三种子方法验证或
V2V4Real 官方 test。新增参数训练暂时只使用 A100 四卡 worker；完整教师包未齐备，
本轮没有提交新训练，已完成的三个身份种子不重复执行。
