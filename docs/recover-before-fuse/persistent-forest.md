# 可恢复身份森林的持久化长序列后端

2026-09-13 新增 `persistent_forest.py`、`persistent_cache_stream.py` 和
`tools/event_track_v2x/run_persistent_forest_v2.py`。后端可以跨越原有限窗口连续输出，
并接收正式 `DetectionCacheV2` 数据；现有有限窗口实现和历史实验保持不变。

当前已验证长序列合成跟踪、原始 V2 格式到预测格式的接入、关闭后重开、质量界和
状态重放。[训练接入](row-identity-training.md)已补充数据准备、三种子拟合与检查点
运行入口；[持久化分量后端](persistent-components.md)已补充共享预算与原始支持合并。
真实训练、完整真实 validation、学习式计算分配和强基线比较尚未完成。
几何与学习运行入口都保留开发状态，不能当作已验证的论文方法。

## 1. 历史不再按每个分支复制

`PersistentForestTracker` 将原始观测、当前势、共享父指针前缀、条件状态、未展开
前沿和历史输出保存在单个 SQLite 文件中。前沿和 active 集合保存前缀句柄，不保存
每条分支的整段父指针数组。二进制祖先索引用于查询任意历史节点的身份根。

原始观测始终可恢复。跨过决策窗口时不选择唯一 MAP，不删除旧身份分支，也不把
多个身份分支平均成一个连续状态。追加观测使旧叶子成为可继续展开的内部前缀；
如果前沿容量不足，可退回覆盖完整支持的根区域。旧共享前缀和状态仍留在磁盘，
重新推断的展开工作需要重新计费。

这不是无限容量或恒定总内存的实现。前缀记录和 SQLite 页缓存有显式缓存限额；
行质量上界使用随观测数线性增长的标量数组，输出还需收集身份根索引。原始观测、
前缀节点及事件数另有硬上限。数据库和历史输出也随序列增长，不在本版本自动删除。
到达硬上限时事务失败，不能以丢观测、裁候选边或永久截断身份的方式制造完成。

本文件描述原联合森林后端；新增的 `PersistentComponentTracker` 使用同一原始数据
事务实现分量推断，详见[分量说明](persistent-components.md)。两者均未验证真实
密集场景的时间和内存表现，仍需全 train 实测。

## 2. 残余质量与可行动作的风险

设当前完整合法父指针集合为 $\mathcal H$，显式 active 集合为 $A$，未展开前缀
覆盖为 $\mathcal P$。完整叶子和前沿区域两两不交，恰好覆盖 $\mathcal H$。
对于深度为 $k$ 的前缀 $p$，忽略其后根内源帧排除约束，得到

\[
U(p)=w(p)\prod_{i=k+1}^{n}\sum_{j\in\mathcal C_i}\psi_i(j),\qquad
Z_U=Z_A+\sum_{p\in\mathcal P}U(p),\qquad
\eta\le\bar\eta=1-Z_A/Z_U.
\]

实现保存正势的绝对对数权重。旧行重评分不得改变节点或原支持；势的修订号改变后，
旧前缀权重缓存会失效并从当前因子重算。条件连续状态只依赖该前缀的身份配置与
原始观测，不依赖该分支的后验质量，所以不需要因权重修订而混合兄弟分支状态。

当前动作选择没有宣称完成全部合法动作上的精确 Bayes 搜索。令 $I_d$ 为决策时刻
计入损失的观测索引，损失为该集合上的归一化根身份错误。默认集合为
$I_d=\{i:t_i^{state}\ge\max(0,t_d^{ref}-W),\ t_i^{arrival}\le d\}$，其中
$W$ 为 `state.window_us`；`decision_indices` 可显式指定同一合法索引集合。
所有输入仍须先满足实际到达约束。空集合的损失定义为 0，但不能把这个 0 解释为
所有仍在输出的历史轨迹都没有身份风险。这个代理损失不是 HOTA、IDF1，也不是
改写旧输出后的指标。

令 $q=p(\cdot\mid A)$，$m_i(r)=q(r_i=r)$。若放松联合合法动作约束，让每个索引
独立选择根，便得到条件 Bayes 风险下界

\[
\underline R_q=\frac1{|I_d|}\sum_{i\in I_d}\left(1-\max_r m_i(r)\right)
\le \min_{a\in\mathcal A}R_q(a).
\]

对于任意合法实际输出动作 $a$，令 $\delta(a)=R_q(a)-\underline R_q$。用与完整模型
相同的合法动作集合，按保留与遗漏质量分解，有

\[
\begin{aligned}
R_p(a)-\min_bR_p(b)
&\le\eta+(1-\eta)\left[R_q(a)-\min_bR_q(b)\right]\\
&\le\eta+\delta(a)\le\bar\eta+\delta(a).
\end{aligned}
\]

后端在 active 动作和「保持旧动作、新观测先新生」的合法回退动作之间选择。
若风险估计不满足配置阈值，使用回退动作，并重新计算该动作自己的风险界；不会
把其他动作较小的界贴到回退结果上。active 为空时只给损失范围的平凡界 1。

上述是固定有限模型内的代数结论。实现使用浮点裕量，未采用区间算术；模型校准、
支持门控排除正确边的误差和真实后验误差均不被这个界覆盖。质量界不是学习得到的
confidence，展开次数也不能代替实际延迟或内存测量。

## 3. 条件状态增量更新与迟到重放

每个共享前缀记录同一身份根的上一个观测更新。若新观测的排序键晚于该根已保存的
最后原始观测，则按原 CI／运动更新继续计算，并仍将状态保存在最后观测时刻。
输出时刻的传播另做一次，不在任意窗口边界增加一次传播。

若新观测插入了更早的状态时间顺序，后端沿同根历史链取回原始观测，由 SQLite
按 `(state_us, source_id, node_id)` 排序，再逐条重放。不使用兄弟身份分支的平均
状态猜测早期关联。新生分数、年龄和存活分数仍来自检测；分数时刻见证沿历史链
流式读取，避免在每个前缀状态里复制越来越长的见证列表。

每个 active 分支和实际输出分支都有独立条件状态摘要。旧输出仅追加存储，不会
随当前身份恢复而重写。完整预测格式保持原有 world 坐标、car 类别和稳定 ID 格式。

## 4. 正式缓存接收与评分上下文

`PersistentForestCacheStream` 使用原 `VerifiedForestCache` 校验 V2 范围与来源。
帧元数据、哈希和到达约束通过检查后，才读取检测与特征。检测仅保留 car，采用
固定 raw score 阈值和每帧数量限额。首次接收时刻写入数据库，重复帧不会重载、
改变到达特征或重复计入模型。

接收记录、因子、前缀、状态和输出位于同一数据库事务内。模型或状态重放失败时，
全部回滚；不能留下「已收帧，但其观测未进入跟踪」的分离状态。重开后重试旧事件
直接返回原输出字节，冲突事件拒绝执行。

新增评分协议名为 `persistent-forest-arrival-row-parent-context-v1`：

- 逐条流式扫描时间门控内的旧原始候选，按相同运动距离及索引规则选择候选父节点。
- 每个新节点的评分上下文仅包含自身及选中的父节点，最多 `parent_limit + 1` 个
  原始特征向量；它不等于原全场景或分量上下文网络。
- 学习评分器与几何评分器都输出相同全局节点支持上的势。此适配器不重评分旧行；
  持久化后端本身支持固定支持的旧行重评分。
- 缓存、选择规则、特征 recipe、评分器签名和配置被绑定；重开时不得切换协议。

这个局部上下文是新配置，尚未用真实 train 训练。现有训练夹具只验证数据、参数
更新和推断接入，不是实际学习效果。训练数据构造及同计算预算的 Top-K、
MHT 等比较必须采用同一上下文和因子，不能把上下文变化造成的收益记为恢复收益。

## 5. 容量、保存与重开

`PersistentForestConfig` 的独立限额包括观测总数、单事件新观测数、共享前缀数、
事件数、前缀／行缓存条数、SQLite 页缓存和决策损失索引数。嵌套 `state` 中：

- `window_us` 只控制决策损失范围，不再使序列到期。
- `active_limit`、`max_frontier`、`expansion_budget` 和 `max_model_regret` 控制推断。
- 运动、CI、新生、剪除和最大年龄参数控制状态与输出；`max_replay_operations`
  限制本次新增状态计算及迟到重放，不代表所有 SQL 或评分工作的总耗时。
- 父节点数量、时间和距离参数用于行上下文候选选择。
- 原有限窗口的 `max_nodes`、`max_commits`、动作搜索和分量限额不用于本后端。
  将这些不适用参数改成非默认值会报错，而不是静默忽略。

输出路径必须是新文件且不经过软链接。`close()` 完成正常关闭并返回数据库文件
SHA256；`open()` 同时要求该文件哈希与预期预测提交哈希。测试覆盖的是正常关闭
后的恢复和事务异常回滚，不是断电、强杀进程或损坏热日志的恢复承诺。
恢复材料应保存这两个哈希和对应数据库，不能只保留日志中的运行状态。

## 6. 完整 validation 的运行入口

`run_persistent_forest_v2.py` 复用原严格的 SPD official-val 日程解析器，要求
3316 个输出帧、21 个序列和 prediction-only 字段；缓存要求完整 val 范围。
它不接受 test 或 GT，不训练，也不发布 ClearML。

来源和配置在运行前写入 `plan.json`。每个序列使用独立数据库；预测与审计逐帧写入
原评价格式。只有全部输出完成且源码哈希复核通过，才生成完整 validation 回执。
失败会留下 `failure.json`，明确标记已有输出不属于最终结果。

源信息时刻不晚于 `reference + 100ms` 的配对帧，在这个决策时刻作为快照送达。
较晚帧在读载荷前被排除。这是显式的配对快照输入协议，不是测量得到的网络时延，
也没有将实际墙钟推断耗时纳入 100ms 截止条件。

原入口固定为几何开发基线，新增 `run_trained_persistent_forest_v2.py` 读取受校验的
训练权重。配置不是严格 train 选择结果，两者均为 `paper_eligible=False`。
它记录阶段延迟分位数、进程峰值 RSS 和数据库大小，但尚无真实运行结果。
不要在全 train 资源设计完成前用已见 val 调参，也不能把小型 V2 格式接入测试
当成完整官方 validation 已完成。
