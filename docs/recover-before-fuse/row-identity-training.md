# 持久化身份森林的训练接入

本版本实现了 car 身份模块的训练数据准备、三种子拟合、权重校验加载，以及接回
持久化跟踪的运行入口。所有研究代码位于 transvision；论文构建工具保持原位。

当前证据来自小型合成标注和正式 V2 格式测试夹具。尚未运行新模块的完整真实
train 或 validation，不能据此报告跟踪增益。[持久化分量推断](persistent-components.md)
已接入相同逐行评分器和 V2 输出；学习式展开优先级、同资源强基线和第二数据集
验证仍未完成。

## 1. 训练与推断使用同一上下文

`forest_row_context.py` 提供唯一的候选构造实现。训练准备和
`PersistentForestCacheStream` 均调用它，不分别维护两套候选逻辑。

每个新观测只使用已经到达的历史观测和同一到达批次中排在前面的观测。排除同一
源帧后，按原始状态的运动传播距离门控，再按距离和全局索引选择父节点。
上下文包含这些父节点及当前查询，最多 `parent_limit + 1` 个原始特征向量。
这不是全场景注意力，也不是此前的全分量上下文。

特征协议为 `recover-before-fuse-physical-world-cache203-v1`。冻结的 128 维外观
向量不变，其余坐标、时间及协方差字段使用现有物理世界坐标构造。
旧配对模型的 203 维输入不等于这个协议，不能直接复用其权重。

训练和现有 validation 入口采用相同的配对快照约定：在车端参考时刻后 100 ms
接收可用的双方帧。源信息尚未到达时，在读取载荷前排除该帧。完整 train 缓存的
未配对源帧仍被计入数据范围审计，但不会被额外塞进模型输入。这不是实测网络时延，
也不是墙钟实时性保证。旧行势在该适配器中保持不变。

批量训练直接复用 `RecoverableIdentityModel` 的编码器、注意力和各评分头。
历史父节点使用历史嵌入，跨端配对使用双方上下文嵌入，与逐行推断一致。
测试覆盖不同源顺序、上下文长度、时间戳和浮点精度；关闭 dropout 时还比较全部
参数梯度。开启 dropout 的训练不承诺与逐行调用产生相同随机掩码。

## 2. 标签来自精确身份引用，不进入模型输入

旧监督文件只提供跨端二元配对，缺少时序身份标签。新入口重新读取已校验的
train 转换结果，以 `(sequence, source, track_id)` 表示源内身份，用 cooperative
标签中的源帧、track ID 和 annotation token 精确连接两端。

重复 GT track ID 不能靠选取其中一个 token 消除。如果一个连通身份在同一源帧
包含多个 GT 实例，整个连通身份标记为歧义。同源不同 track ID 被连接后，只有
不存在同帧共存冲突时才可作为连续片段。跨端缺少链接不自动构成负例。

每个实际接收的源帧先按完整原始检测分数排序，在同类别内进行严格小于 2 m 的 XY 匹配，
每个 GT 只匹配一次。随后才取 car、分数阈值及数量限额内的检测。删去高分候选
不会把低分重复检测重新提升为真阳性。这个规则与既有监督准备一致；它是监督
匹配定义，不是检测正确性的无误判保证。

每个训练行的结果分为：

| 类型 | 处理 |
| --- | --- |
| `parent` | 同身份的多个候选父节点共同为正样本；未知关系不作为负样本 |
| `birth` | 全部先前已接收预测中，没有同身份或未知关系，才监督为新生 |
| `out_of_support` | 已见过同身份，但正确父节点不在当前候选中；排除损失并计数 |
| `uncertain_birth` | 先前存在无法排除的身份关系；不制造新生标签 |
| `ambiguous` | 重复 ID 或身份冲突；排除身份损失并计数 |
| `unmatched_prediction` | 未匹配 GT 的查询不训练身份；存在性继续由检测分数负责 |
| `non_car` | 不训练，也不报告 pedestrian 结论 |

保守的未知关系规则可能减少有效监督，必须报告各类型数量及候选覆盖，不能只报告
保留下来的低损失样本。完整 train 的未来标注可以帮助确定离线身份真值，但未来
观测、GT 框、GT ID、GT 速度和下一帧标注均不进入神经网络。

## 3. 多正样本损失及其界限

令当前行的已知选项集合为 $K$，其中正确父节点集合为 $P\subseteq K$；新生也是
一个选项。行势的未归一化对数分数记为 $z_j$。训练使用

\[
\mathcal L(z;K,P)=\log\sum_{j\in K}e^{z_j}-\log\sum_{j\in P}e^{z_j}.
\]

当 $K$ 包含完整候选、$P$ 包含全部正确父节点时，这是局部行模型对正确选项集合
的负对数概率。多个正确父节点不会相互作为负例。对任意选项 $k$，有

\[
\frac{\partial\mathcal L}{\partial z_k}
=\mathbf1[k\in K]\frac{e^{z_k}}{\sum_{j\in K}e^{z_j}}
-\mathbf1[k\in P]\frac{e^{z_k}}{\sum_{j\in P}e^{z_j}}.
\]

因此，未知选项 $k\notin K$ 的直接梯度为零。对未知选项掩码后的损失是受限选项
上的局部替代目标，不是完整森林的联合似然，也不保证真实概率校准。无有效正样本
的行被排除并计数；整个批次没有监督时拒绝计算，不能报告伪造的零训练损失。

合法一对一身份配置、残余质量上界和最终动作风险仍由确定性森林推断负责。
不能把局部 softmax、训练准确率或该损失值替代为完整后验质量界。

## 4. 数据与检查点约束

`prepare_forest_training.py` 要求受校验的完整 SPD train V2 缓存：46 个序列、
16,338 个源帧和 7,445 个 cooperative 配对。转换 PKL 仅接受代码中固定的两个
受信哈希；先校验实际读取的字节，再反序列化，不接受任意外部 PKL。
旧 `target-audit.json` 只提供元数据与标签文件的字节身份，不能替代时序标签。

每个序列写一个 NPZ，原始节点只存一次，上下文保存整数索引。GT 框和身份值不
进入 NPZ，监督只保存多正样本掩码、已知关系掩码和排除原因。manifest 绑定缓存、
数据准备源码、特征协议、门控参数、配对时序、监督匹配规则和每个分片的哈希。

`train_forest_identity.py` 在首次更新前检查全部分片与行，保存计划和源码哈希。
训练按随机序列顺序、序列内随机行顺序遍历，一次加载一个序列，使用三个固定
种子 `1337 / 2027 / 3407`。每轮必须覆盖全部有效监督行，不以部分采样冒充完整
训练。最后一轮生成权重，不在 validation 上选择种子或检查点。

检查点绑定结构、权重、训练数据、种子、特征及上下文协议，以及双方检测器、
外观提取器和校准文件的哈希。推断以 `weights_only=True` 加载并冻结权重；
参数、字节或协议不一致时拒绝加载。验证缓存必须使用相同的冻结上游模型。
正式训练还要求数据准备源码哈希与当前实现一致；检查点加载复核评分核心源码。
更新这些实现后必须重新准备或训练，不能仅沿用旧协议名称。

当前缓存的检测器与校准使用全 train，属于 in-sample，**不是 OOF**。
本入口是固定末轮的开发训练，不是严格序列隔离的模型选择流程。
将来若要选择超参数，仍须补齐上游拟合集隔离及对应折缓存，不能给现有结果补贴
「未见留出集」标签。所有新训练和跟踪回执保留 `paper_eligible=False`。

## 5. 运行与失败处理

运行目录为 transvision，所有输出目录必须尚不存在。源码同步和远端实验需要
相应权限；现有 ClearML 发布授权不涵盖本轮源码、训练产物或完整预测流。

1. 运行 `tools/event_track_v2x/prepare_forest_training.py --help`，指定已核对的
   `--cache`、`--converted`、`--projection`、`--target-audit`、其 SHA256 及新输出目录。
   成功后读取新 `manifest.json` 的哈希及各类监督数量。
2. 运行 `tools/event_track_v2x/train_forest_identity.py`，提供 `--data`、
   `--manifest-sha256` 和新 `--output`。默认固定 10 轮、batch 64；这些是开发配置，
   不是已由严格 train 选择验证的参数。通过 `--device` 指定经过验证的运行设备。
3. 完整 train 数据和训练回执核验后，使用
   `tools/event_track_v2x/run_trained_persistent_forest_v2.py` 接入指定种子的权重。
   入口仍要求 SPD 完整 official-val 日程与缓存；夹具权重不能作为正式训练结果。
   三个种子应分别运行，不用已见 val 挑选最好种子。

成功回执与中间日志不同。准备或训练失败时保留 `failure.json` 及已有产物，不生成
完整成功回执；重新运行使用新目录。本版没有中断训练续跑功能。跟踪输出与数据库
仍遵守[持久化后端](persistent-forest.md)的原子提交与关闭后重开约定。

SPD 的 test/test_A 继续排除。V2V4Real 按用户已授权的官方 test 做冻结后的最终
评估，但本训练入口仅实现 SPD，不能拿它替代第二数据集适配和验证。
