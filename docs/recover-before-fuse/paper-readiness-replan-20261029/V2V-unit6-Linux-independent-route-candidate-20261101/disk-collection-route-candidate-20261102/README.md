## 实际容量怎么判

生产资源探针514c4db8…的18:01样本曾证明生产端空闲5,624,844,775,424字节、有效内存余量57,932,861,440字节及四卡UUID/空进程符合原合同；样本18:16已过期，不能用来当前放行或推断宿主磁盘已绑定给新任务。112 19:17系统盘只有约10.52GB，tmpfs约15.09GB；不得只因生产端磁盘宽裕而声称112能完整收集。

生产终态后，先从注册seal核对原304事件与七文件的准确大小，再对同一注册压缩归档完整流式SHA、gzip CRC/ISIZE及全部成员大小预扫描，不保留额外整包副本。记C=所有注册压缩产物字节，E=全部需展开成员字节。原disk公式保持：

    available_disk > C + E + 26,690,158 + 512MiB + 8GiB
    effective_available_RAM > 8GiB

进入收集前再读当前Task注册状态、文件系统挂载、容量及原完整证明；不使用历史unit0大小估计unit6输出。满足后才调用未改的原收集器逐文件完整SHA，然后运行原六项及原终态独立读取器。容量不够则保持原注册资产、记录具体缺口，不启动收集、不清数据、不降低门槛。

所有源码包、来源及结果须保持原字节SHA。新实际运行入口必须在导入前和每个阶段边界核对本合同及新模块SHA；现有候选只是准备层，不能绕过这一外层来源锁或直接替代旧已批准controller。实际Task上的源/运行环境、挂载与当前容量尚未通过，原release flag未写，未消费unit6生产或独立数值次数。
