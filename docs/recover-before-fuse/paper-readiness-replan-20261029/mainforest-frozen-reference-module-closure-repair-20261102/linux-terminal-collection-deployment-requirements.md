# 完整验收新尝试前：Linux终态收集部署要求

collect_reference_alias_outputs.py已经绑定新包与新独立验证器，保留原完整注册资产SHA及expected_artifact_bytes+5GiB容量门槛。该脚本必须在Linux运行，Mac不执行哈希、解包、来源或数值验收。112目前仅约10GB可用，不能把它当作35GB级完整产物收集主机，也不能为启动重跑降低原容量门槛。

优先候选是同一A100主机的合格空闲worker，经ClearML执行独立终态收集；不SSH，不抢占其他四卡/八卡任务。独立收集作为后续单独Task/进程，只有生产Task已终态、物理资源准入及原注册资产身份核验通过后才能执行。需要原冻结镜像、ClearML SDK、32696文件原命名空间、原包及支持验证器、新100成员job和新独立验证器的完整源码SHA绑定。原生产workspace不能直接当独立验收证据，仍完整核验已注册归档全部字节、成员和独立语义收据。

收集端须重新实测目标文件系统空间，容纳全部注册资产总大小加5GiB；另需原verify_registered_attempt_archive对选中json/jsonl/log成员的独立selected_bytes+5GiB空间检查。重用已通过的文件只能依据精确注册SHA和稳定文件身份，不根据路径存在跳过验证。原生产目录、归档、失败结果均保留。

新收集Task入口/冻结源码部署、具体来源发布范围及精确单次授权还未准备完成；当前文档是准入设计，不是已验机器或已投递收集器。生产重跑的新批准请求应覆盖生产入口和具体独立收集范围，不能先启动新生产再补关键收集依赖。若采取流式保存路线，需完成与原完整字节/成员校验等价的独立审核和对应授权，不把范围日志读取升级为整包收集。
