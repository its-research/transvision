## 2. 新入口与一致性检查

`run_train_inference_diagnostic.py` 要求真实封存 train 缓存、完整协同元数据、明确序列和完整 train 身份检查点。它与教师入口共用 `verified_train_rows`，先核对完整输入日程，再选择一个完整序列；不接受 val/test 或截断后的协同元数据。低层测试 API 显式记录 `fixture-only`，不能由汇总入口改标为真实 train。

三次运行分别启动新解释器，均固定 BLAS／OpenMP 和 PyTorch 线程数。原版本先启动，随后另外两个进程并行启动，以缩短机制诊断等待。因此部分运行时段重叠、共享本机 CPU 和存储；本轮耗时不用于同算力、尾延迟排名或加速比结论。正式资源实验仍须预先安排完整重复。

计划绑定模型目录、初始化文件和声明的回放工具依赖。运行结束重新核对源码和输入；只有额外的 `development-inference-receipt.json` 才表示该诊断验收完成。模型与回放依赖在活跃运行期间保持不变；独立评估工具不属于预测器依赖。

`audit_train_inference_comparison.py` 重新核对计划、预测、审计、计时、关闭数据库及完成回执，检查全部预声明后端的状态。成功运行必须具有相同序列、检查点、状态模型，以及逐帧原始观测与行势摘要。可选教师参照用于检验：离线试算回滚后，原版本的预测是否与纯推断完全一致。

有失败运行时，汇总记录 `partial_due_to_failed_runs`、`complete_backend_comparison=false`，保留失败前缀和当前产物摘要。不允许只传两个成功后端，静默删除第三个失败后端。输出 ID 数、只出现一帧的 ID 数和相邻输出集合变化仅是行为诊断，不是 IDS、IDF1 或 GT 判定的错误持续时间。
