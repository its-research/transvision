# 持久化分量推断：可恢复身份类与共享预算

2026-09-13，`PersistentComponentTracker` 已接入正式 `DetectionCacheV2` 接收流程、
逐行学习势和原跟踪预测格式。它按完整候选支持划分分量，在一个 SQLite 事务中
保存原始观测、身份前缀、条件状态、接收记录和输出。

当前证据来自穷举小场景、120 次连续输出和 V2 格式测试夹具。尚未完成新模块的
完整真实训练、SPD 全 validation 或 V2V4Real 官方 test 验证。默认计算分配是
确定性规则；后续已增加[学习式搜索优先级](learned-allocation.md)，仍待真实训练
与验证。本实现与运行入口均不构成已验证的论文增益。

后续已接入[固定宽度 beam 对照](fixed-beam-baselines.md)，包含逐节点剪枝、旧组合
预选后整批排序，以及[完整旧保留组合联合排序](joint-beam-ranking.md)，使用相同
学习势及状态代码。它们不是已复现的经典 MHT，仍需强基线与
同资源的真实实验。`--max-model-regret 1` 可关闭完整方法的风险阈值回退，用于
预先声明的条件 Bayes 解码对照；不能据此标记为已经完成纯恢复消融。

## 1. 模型与可恢复对象

节点按实际接收顺序编号。每个节点选择新生或一个先前候选父节点；完整父森林
决定每个原始观测的身份根。一个身份不能包含同源同帧的两个观测。势函数在当前
决策时刻固定，不依赖正在枚举的父路径；现有学习适配器不修改旧行势。

候选图的无向连通分量由**全部候选父边**确定，低分边同样参与连通判断。
已被上游距离、时间或数量门控排除的边不属于模型支持，不能由此处的恢复机制
找回，其误差也不包含在残余质量界中。对该固定模型，有

\[
\mathcal H=\prod_c\mathcal H_c,\qquad
w(h)=\prod_c w_c(h_c),\qquad Z=\prod_c Z_c.
\]

原因是父路径和同源同帧互斥均位于分量内部；局部合法配置的任意组合仍合法。
若新增跨分量约束或依赖其他分量身份选择的势，上述分解不再成立。

共享数据库只保存一份原始观测与当前行势。分量视图通过不可变成员索引引用它们，
不在每次合并时复制原始特征。每个分量独立保存父指针前缀、前沿和条件状态。
决策窗口只限制当前损失索引，不删除窗口外的身份历史。

## 2. 对相同完整身份历史精确求和

不同父森林可能表示同一身份历史。若直接按父路径保留 Top-K，多条等价路径会
占用多个位置。本实现只合并具有**相同完整根分配序列**的父路径，不合并仅当前
状态接近、短窗口身份相同或高斯矩相同的分支。

令 $g=(r_0,\ldots,r_{n-1})$ 为完整身份根序列，$w_i(p)>0$ 为行势，$-1$ 表示
新生。对合法的根分配前缀，定义转移类权重

\[
T_i(g)=
\begin{cases}
w_i(-1),&r_i=i,\\
\displaystyle\sum_{p\in P_i:\ r_p=r_i}w_i(p),&r_i<i.
\end{cases}
\]

每条路径的权重是各行势的乘积。同一根序列内，允许的父选择集合只由该根序列
和固定候选支持确定，因此有限分配律给出

\[
W(g)=\sum_{h:\operatorname{roots}(h)=g}\prod_iw_i(h_i)
=\prod_i T_i(g).
\]

实现以最小合法父索引保存类的代表路径，计算权重时使用 `logsumexp`，不是取
最大父分数。原始行势保留全部父选择。三个节点的对照包含 6 条父路径、5 个身份
类，单位势下类权重为 $1,1,1,1,2$；重评分后，两条等价路径的权重仍按和计算。

条件状态按每个身份包含的原始观测、源时刻及确定性顺序进行 CI／运动重放，
不依赖该身份内部选中了哪条父边，故同一类的条件状态也相同。若未来加入依赖
父路径的状态更新、历史网络状态或额外转移势，必须重新证明等价性，不能沿用
这一压缩。该操作不减少不同完整身份历史的数量，也不是窗口边界边缘化。

## 3. 前沿覆盖与绝对质量

显式集合 $A_c$ 保存完整身份类及其绝对权重；前沿 $F_c$ 是互不重叠的前缀区域，
与显式类共同覆盖完整局部支持。增量候选可在一个尚未展开完的前缀区域内先产生
完整类，因此显式类与前沿区域**允许重叠**，不能直接把两者质量相加。

对前缀 $s$，放松未来行之间的合法性限制，使用逐行势和的乘积作为区域上界
$U(s)$。记 $D(F_c)$ 为所有前沿区域的并集，则

\[
Z_{U,c}=\sum_{s\in F_c}U(s)
+\sum_{g\in A_c\setminus D(F_c)}W(g)\ \ge Z_c,
\qquad Z_{K,c}=\sum_{g\in A_c}W(g),
\]

\[
\eta_c=1-\frac{Z_{K,c}}{Z_c}
\le\bar\eta_c=1-\frac{Z_{K,c}}{Z_{U,c}}.
\]

区域内已经显式找到的类不再重复加入上界。一个类被移出显式集合时，若前沿已
覆盖它，也不再添加重叠区域。前沿展开、候选插入和容量重启均检查这种覆盖关系。
整体保留集合无需枚举，其遗漏质量上界为

\[
\eta_{\mathrm{product}}\le 1-\prod_c(1-\bar\eta_c).
\]

这是固定有限模型内的数学结论。浮点计算采用数值裕量而非区间算术；审计明确
标记 `formal_numeric_certificate=False`。模型误差、门控支持误差及真实校准误差
不由此式约束，归一化后的显式权重也不是完整真实后验。

## 4. 实际动作风险与共享搜索

损失采用当前索引集合内归一化的身份根分配错误，范围为 $[0,1]$；它不是
HOTA、AssA 或 IDF1。令 $\lambda_c$ 为分量内损失节点数占比，$q_c$ 为显式集合
上的条件分布。用合法动作集合的松弛获得条件 Bayes 风险下界 $\underline R_c$，
对实际输出动作 $a_c$ 计算

\[
\delta_c=R_{q_c}(a_c)-\underline R_c\ge0,\qquad
\operatorname{Regret}(a)
\le\sum_c\lambda_c\min\{1,\bar\eta_c+\delta_c\}.
\]

逐分量对保留／遗漏质量分解，再利用合法动作空间的笛卡尔积分解，即得此式。
前沿为空且全部合法身份类已显式保留时，直接枚举得到准确的条件 Bayes 下界。
测试中存在条件身份风险为 $29/92$、Bayes regret 为零的例子：零 regret 只表示
当前模型中没有更优动作，不表示身份一定正确。

当前策略优先处理 $\lambda_c\bar\eta_c$ 最大的分量，所有分量共用一个搜索预算。
两种操作分别计数：

| 操作 | 计费方式 |
| --- | --- |
| 从既有完整身份历史向新观测生成贪心候选 | 每扩展一个新节点计 1 个 `proposal_steps` |
| 细化可恢复前沿区域 | 每次前缀细化计 1 个 `expansions` |

`search_steps = proposal_steps + expansions <= search_budget`。贪心候选只增加可用
完整动作和质量下界，未展开支持仍保留。该计数不是统一 FLOPs，也不包含评分、
界更新、回退路径构造、映射重建、状态重放、SQL 或审计开销。它不能代替同延迟、
同内存对照，也不能证明该分配规则最优或已实现学习式计算分配。

拟选动作的整体风险界超过阈值时，回退保持先前输出身份，新观测先新生。
实现重新计算实际回退动作的风险，不沿用被拒绝动作的较小界。界过松时不会
宣称输出已经获得保证；零搜索预算也保留完整可恢复支持。

## 5. 合并、恢复与事务

新观测连接旧分量时，创建联合分量，从全部原始候选支持重新建立可恢复前沿。
原分量的成员映射和前缀保留在磁盘上。旧输出身份配置被提升为联合回退动作，
并用于生成新观测的增量候选；不是只把旧 Top-K 做笛卡尔积作为新的完整支持。
所有输出 ID 均由原始出生节点产生，不因局部索引重排或分量编号改变而重命名。

恢复审计只比较本次实际选择的完整身份类与前驱的显式集合／输出，记录前驱分量、
当前输出句柄、投影摘要，以及此前是否已经展开。恢复配置可由前缀和成员映射
重建，不在每帧审计中复制完整父历史。恢复事件不等于可见轨迹 ID 改善，也不
自动证明错误减少；需要关联 GT 错误事件作独立分析。

已有测试在旧行势完全冻结时追加新观测，使此前未展开的旧身份配置进入当前
决策；继续细化期间因子摘要不变。另有旧行重评分恢复的独立测试。二者均验证
旧预测字节不变，恢复仅影响当前和未来输出。

接收记录、原始数据、分量映射、前缀、状态与输出统一提交。状态保存失败或容量
超限会回滚全部变更，包括本次新建的分量表；重试重复消息返回原输出字节。
恢复协议校验正常关闭后的数据库 SHA256 和预测链头。它不承诺断电、强杀进程或
损坏热日志后的自动恢复。归档分量的因子视图引用当前共享行势；历史原评分由
不可变追加／重评分事件记录保存，不能把该视图称为冻结的旧后验。

## 6. 容量与运行边界

共享限额覆盖全部分量的前缀总数、活跃前沿总数、前缀／行缓存条数、状态重放
操作数，以及含归档版本的成员映射行数。合并后释放旧分量的内存缓存和界数组，
原始载荷不复制；每个活跃分量仍有随其节点数线性增长的界数组。

数据库、历史事件、归档前缀和 SQLite schema 仍会增长。缓存条数上限不等于进程
RSS 上限；一个巨大连通分量仍可能过慢或超限。完整 train 的分量规模、峰值 RSS、
数据库大小和尾延迟检查尚未完成，不能据此宣称适用于真实密集场景或满足实时性。
真实超限时明确失败，不通过删除候选边或原始观测制造通过。

运行入口为 `tools/event_track_v2x/run_component_persistent_forest_v2.py`：

- 不传检查点时为明确的几何开发基线。
- 学习模式必须同时提供检查点及 SHA256，检查点必须标记完整官方 train 训练，
  且检测器、外观与校准文件身份与 val 缓存一致；小型测试权重被正式入口拒绝。
- SPD 要求完整 official-val：3316 个输出帧、21 个序列、7189 个源帧。仅 car，
  不读 GT、test 或 test_A，不在已见 val 上选检查点。
- 复用 `reference + 100 ms` 的配对快照到达协议，不把它称为实测网络时延。
- 逐帧输出保持原评价格式；全部完成且源码哈希复核后才保存完整运行回执。
  不上传 ClearML，不把部分输出标记为最终结果。

三种子训练与检查点合同见[训练接入](row-identity-training.md)。V2V4Real 的最终
评估按用户授权采用官方 test，但本入口只适配 SPD，不能用其回执替代第二数据集
实验。现有配置和上游 in-sample 缓存仍不构成严格隔离的 train 模型选择流程。
