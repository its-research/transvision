## 等权选择点目标与 DDP 归约

沿用[学习分配定义](learned-allocation.md)的 18 维因果特征和有符号模型进展目标。
网络为 `Linear(18, hidden) → tanh → Linear(hidden, 1) → tanh`，默认 `hidden=32`，
使用 float64。对选择点（候选组）$g$，候选数为 $n_g$，定义

\[
\ell_g(\theta)=\frac{1}{n_g}\sum_{i=1}^{n_g}
  \bigl[f_\theta(x_{gi})-y_{gi}\bigr]^2.
\]

全局 batch 包含 $G$ 个选择点，目标是 $G^{-1}\sum_g\ell_g$，不是所有候选行
等权。默认 `--global-batch-groups 64` 表示 64 个选择点，候选行数可变。
例如，两组分别包含 1 行和 9 行，只有第一组误差为 1：等组目标为 0.5，等行目标为 0.1。

设进程数为 $W$。按全局组序号跨 rank 交错分配，不补齐、不丢弃、不重复组。
rank $r$ 反向传播的本地损失为

\[
L_r=\frac{W}{G}\sum_{g\in\mathcal G_r}\ell_g,
\qquad
\frac1W\sum_{r=0}^{W-1}\nabla L_r
=\nabla\left(\frac1G\sum_{g=1}^{G}\ell_g\right).
\]

右式是 DDP 平均梯度后得到的全局目标梯度。尾 batch 的空 rank 使用依赖全部参数的
零损失参与归约，不伪造训练样本。梯度归约后统一裁剪，再执行 Adam。
同一初始参数下的梯度对照已通过，不意味着批量 Adam 与旧版逐组 Adam 的更新轨迹相同，
也不保证不同 GPU 的逐位一致或四卡加速。

## 数据、选择与运行约束

正式数据预检要求：train、当前源码、固定特征／目标定义、无未来或 GT 输入，
以及完整 46 序列教师导出标记和回执摘要。逐分片重新核对组数、行数、字段和文件摘要。
拟合部分若全部目标绝对值不超过 `1e-12`，拒绝启动。存在非零目标也只证明有数值信号，
不证明目标与真实身份错误相关。

序列按固定哈希 `priority-holdout-v1:<sequence>` 排序，前 `floor(46/5)=9` 个作为
优先级模块留出，其余 37 个参与优化。默认 10 轮，固定最后一轮，不按留出损失选择
检查点。每个 epoch 单独记录 fit／holdout 组数和候选行数，核对四个 rank 覆盖及同步参数。
改变留出目标不改变训练权重的测试已通过。

完整 teacher 标记不表示所有 train 序列参与优化。上游身份势可能已使用留出序列，
因此保持 `strict_pipeline_isolated_selection=False`、`final_full_train_refit=False`。
不读取 SPD val／test；V2V4Real 官方 test 不属于此训练入口。

各 rank 在创建输出和初始化优化器前核对种子、拟合配置、清单摘要与数据模式。
有效但不一致的配置立即报错，不进入不一致的训练循环。正式运行还核对同一主机、
完整 rank 集合、不同 CUDA 设备和 GPU UUID。错误或缺失 UUID 不能作为四卡证明。

单个任务保存 `plan.json`、`<seed>/epochs.jsonl`、`weights.npz`、`checkpoint.json`
与最终 `receipt.json`；失败单独记录，已有目录不覆盖。检查点可由原冻结优先级加载器
读取；额外的 `training_source_sha256` 绑定训练器及其依赖。单种子回执不宣称三种子完成，
全部运行继续标记 `paper_eligible=False`。

## 四卡 ClearML 控制器

新增 `tools/event_track_v2x/run_clearml_allocation_policy_ddp.py`，用于一个 worker 上的
单种子四卡训练。不同种子可由专用提交器分配到不同物理机；本控制器本身不创建队列、
不选择或修改 worker，也未在真实 ClearML 容器执行。

启动时将 API／文件地址限定为授权服务器 `10.100.35.118`，分别以 5 s TCP 检查
8008／8081 端口；检查失败直接退出，不切换到其他服务器。随后核对执行源码摘要、
固定任务参数、四张 A100／5090 的不同 UUID 和基础 GPU 算术。
参数固定为 10 轮、每全局 batch 64 个选择点，拒绝 V100、少于四卡及 CPU 回退。

通过 ClearML 认证下载绑定包，只接收指定服务器上的源码与数值训练组归档。
解包逐项核对文件清单、体积、摘要及普通文件类型，拒绝额外条目、遗漏、链接和越界路径。
控制器调用 `torchrun --standalone --nproc_per_node=4`，由既有训练器再次执行完整教师
数据预检与实际 DDP 训练。控制器自身和训练器都不读取官方 val／test 或 GT。

子进程正常退出后，控制器重新核对计划、检查点、NPZ 权重和每一轮记录：

- 配置、冻结数据与源码绑定、fit／holdout 序列必须匹配部署包。
- 四个 rank 必须使用同一 worker，GPU UUID 与预检相同；每个 rank 有实际梯度工作。
- 每轮的选择点、候选行和 batch 数必须完整，参数签名同步，MSE 与各 rank 损失和一致。
- 检查点必须是最后一轮的同步参数，权重确实变化，能由原冻结优先级加载器读取。

只有全部检查通过，才上传本任务新产生的优先级 NPZ、检查点清单、训练计划、最终回执
和逐轮记录，并回读核对摘要；每项最多 16 MiB。不上传训练组、GT、教师追踪或预测流。
`torchrun` 非零退出时，不执行结果验收和上传，也不输出训练完成标记。
