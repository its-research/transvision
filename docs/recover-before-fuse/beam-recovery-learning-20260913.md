# 共享 beam 后端的学习式恢复计算分配

学习式优先级和离线教师现已接入 `BeamRecoveryTracker` 使用的同一个恢复执行器。
正式 `DetectionCacheV2` 接口与预测格式不变。新路径只改变额外恢复计算的分配顺序，
没有修改冻结身份势、候选支持、原 node-beam 阶段、状态融合公式或最终解码损失。

这项接入补足了[恢复开关对照](beam-recovery-control-20260913.md)中尚未连接的训练路径，
不是新增训练已经完成，也不证明真实跟踪增益。此前的负结果和原产物继续保留。

2026-09-14 已完成[四条完整 train 教师的标签质量诊断](teacher-label-quality-20260914.md)。
当前四序列的标签较稀疏，低 MSE 不能单独证明调度有效；完整教师集合、优先级
训练及真实同资源收益仍待完成。下文保留原接入阶段的历史运行记录。

## 1. 在线执行与离线教师

实现位于 `transvision/models/event_track_v2x/beam_recovery_allocation.py`：

- `LearnedBeamRecoveryTracker` 复用冻结优先级网络，根据当前可执行操作的特征选择分量。
- `BeamRecoveryTeacherTracker` 对每个可选分量试算同一项操作，再回滚试算；正式轨迹仍
  使用原确定性调度。训练标签不进入身份评分器、候选生成或最终解码。

两者先完成原 node-beam 阶段，再通过 `_select_recovery` 选择额外计算的分量。
操作类型仍由原 `_recovery_operation` 决定，计算仍由原 `_execute_recovery` 执行。
完整后缀提案只有在预算与容量允许时才可执行，否则沿用前缀细化。

没有新增用学习分数删去合法区域的路径。保留集之外的原始身份支持仍由可恢复前沿覆盖，
数学上界仍由原推断器计算。学习分数不替代质量上界，字段 `priority_is_bound=False`
明确这一点。学习优先级不是概率，也不声称是一项计算的真实期望价值。

教师沿用原试算缓存及 SQL savepoint 回滚：恢复前缀、权重、发现记录、活动集、前沿、
状态计数与共享 LRU 均须恢复。试算中发生异常时，外层事务回滚整个到达事件。
教师的耗时包含额外试算，不能当作部署延迟。

## 2. 特征、目标与适用范围

对当前分量 \(c\)，记原模型决策界为

\[
B_c=\min(1,\eta_c^U+g_c),
\]

其中 \(\eta_c^U\) 是原推断器的遗漏质量上界，\(g_c\) 是原有合法动作解码相对于
独立根松弛下界的优化间隙。试算分量下一项实际可执行操作，得到 \(B'_c\) 与实际
计费步数 \(s_c\)，教师目标保持为

\[
t_c=\omega_c\frac{B_c-B'_c}{\max(1,s_c)}.
\]

因为 \(0\le B_c,B'_c,\omega_c\le1\)，所以 \(-1\le t_c\le1\)。目标保留符号，
不把负值截成零，也不假设增加搜索必然改善这一决策界。它是当前模型内的一步界变化，
不是 HOTA、IDF1、真实身份误差、未来收益或遗漏质量本身。

特征沿用已有的 18 维因果搜索状态，包括遗漏界、条件风险、活动熵、前沿深度、
剩余预算和下一项操作类型。新增适配明确使用 `recovery_budget` 归一化剩余预算，
不能误用继承的 `state.expansion_budget`。操作特征必须描述真正准备执行的
覆盖准入后缀或前缀细化，不能沿用另一后端的候选操作。

`all_recent` 模式使用原决策节点占比作为 \(\omega_c\)。
`arrived_vehicle_raw_xy50` 模式使用已合法到达的车辆位姿计算恢复分配权重，仍不改变
原解码损失范围。此时特征中的历史名称 `loss_weight` 表示分配权重，不能据此声称
解码器已经改用 ROI 损失。`priority_label_weight_scope` 记录具体模式。

原生标签与完整后验并不由这项教师试算提供。[局部标签诊断](retained-identity-label-diagnostic-20260913.md)
已经发现局部指标与原生跟踪指标方向不一致，因此教师目标必须另行验证其实际价值。

## 3. 正式入口和数据约束

`collect_allocation_training.py --beam-recovery` 选择新的教师后端。
此时 `--expansion-budget` 表示额外恢复预算，原 beam 参数保持不变。
该开关与旧 `--frontier-completion`、`--coverage-aware-admission` 互斥。
可选 `--recovery-task-poses` 与对应 SHA-256 必须同时提供，并通过完整缓存位姿核验。

教师入口只接受已封存的 SPD train 缓存。验证集在读取载荷、创建输出之前被拒绝。
关闭恢复时也不能加载优先级或执行教师试算。使用 `--development-sequence` 时必须
回放该 train 序列的完整日程，但不会生成完整 train 验收标记。

训练数据导出读取 `recovery_allocation_trace` 中的试算记录，继续检查目标算术、
特征配方、源码及训练绑定。已有优先级训练、导出和检查点加载格式保留。
绑定包含跟踪配置及冻结评分器；旧 component 后端的优先级检查点不能冒充 beam
恢复检查点。新的同资源实验名称为 `learned_beam_recovery`，必须显式提供优先级检查点。

低层测试可构造冻结权重或微型训练数据；这不构成正式训练来源证明。生产参数训练仍
经内部 ClearML，暂时只使用 A100，每个任务至少四卡，不调度 5090 或 V100。

重复缓存消息原本会直接返回旧回执，绕过 `tracker.step` 的优先级绑定检查。
本轮在该快速返回路径前补充同一项检查；更换策略后重放重复消息会被拒绝。
正常重复消息仍返回原回执，不重写历史输出。
