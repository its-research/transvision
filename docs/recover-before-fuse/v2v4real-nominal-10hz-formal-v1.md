## 时间与在线可用性规则

- 名义周期为 100,000 us，每个序列采用独立零起点。时间轴来自冻结的原始 frame key 到公共帧索引映射，不来自文件修改时间或 GPS 向量。
- 两个 CAV 共用序列帧索引，`source_time_us = frame_index * 100000`。不得各自对可见帧重新紧凑编号后强行配对；缺失源帧保持缺失。映射、排序规则及缺口处理必须随缓存发布；无法无歧义建立映射的序列不通过准入。
- CAV 0 为参考端；主条件为两端零注入延迟。单独报告 CAV 1 注入 100 ms、200 ms 的扰动条件，不与主条件混合汇总。延迟是实验参数，不是观测值。
- 沿用已验证调度边界：`deadline = reference_time + 100000 us`，到达时刻等于 deadline 时可用。源时刻不得晚于参考时刻，观测年龄不得超过 100,000 us。
- `arrival_time = source_time + injected_delay`；从符合源时刻、到达时刻和年龄条件的观测中选取最新一帧，无合法观测则缺失。即使未来帧在 deadline 前到达，也不得用于当前决策。
- 迟到旧帧可以在后续决策中按同一规则使用；恢复只改变当前及未来输出，历史提交不可重写。
- 保留源时刻、到达时刻、参考时刻、deadline 和观测年龄。坐标变换不等于运动外推，不能把陈旧框直接称为当前目标状态。

100 ms 注入延迟在上述 inclusive deadline 下与零延迟允许相同当前帧，这是预设边界，不构成鲁棒性收益。需要研究不同的 deadline 或年龄窗口时，先在 train 内冻结独立配置再评价。

## 不随时间协议改变的约束

- 候选保持原始全类别 `raw score >= 0.05 / top64`，主候选集合不做前置 NMS，只在评价与汇总层取 car。旧 car-first 协议保持隔离。
- official train 用于训练及训练内开发；official_test 仅用于冻结后的最终评价。此次授权不包含修改 train/test、剔除采集组或用 test 选择权重。
- 已确认的 294 种跨 split 相同点云内容仍是准入缺口。时间轴改为标称值不能解决数据重叠；必须给出可核验的来源及处理决定，不能直接宣称独立泛化。
- 检测器、embedding、身份模型、优先级模型和校准器分别绑定来源、训练范围及选择回执。来源未核实的公开权重不得因协议改名而自动合格。
- GT 只进入训练监督或独立评价；不进入在线候选、优先级、恢复或选择策略。
- 保持三种子 1337、2027、3407，train 内检查点选择、资源扫描和冻结。固定输入机制比较使用相同候选、势函数、可用性和资源计量规则。
- 所有新缓存、检查点、预测、评价与统计显式绑定本协议 ID、配置哈希、帧映射哈希及其父资产；与实测时钟、旧代理诊断和 car-first 结果不得直接混排。
