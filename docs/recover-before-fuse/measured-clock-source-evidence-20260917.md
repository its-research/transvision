# 历史实测时钟协议：来源证据清单

本文件记录 2026-09-17 当时的资料请求边界，不是已取得证据、发送记录或当前正式实验协议。自 2026-09-20 起，V2V4Real 正式实验采用 [`v2v4real-nominal-10hz-formal-v1`](v2v4real-nominal-10hz-formal-v1.md)；实测时钟材料不再是该变体的前置条件，但仍可支持未来单独的实测协议。检测器来源、数据重叠和公开基线材料要求继续有效。

## 必需材料与验收条件

| 对象 | 需要的数据方材料 | 收到后的验收 |
|---|---|---|
| 逐帧采集时刻 | 按 sequence/CAV/frame key 对应的原始传感器时间表，或可重建它的 bag/pcap/日志；包含单位、时钟域与起点 | 与现有 PCD SHA-256 或明确采集 ID 逐帧绑定；覆盖完整 train/test；拒绝帧号乘 100 ms 的推定时间 |
| 双车时间同步 | GPS/PPS/PTP/设备时钟校准方法、偏移/漂移和跨端配对说明 | 核验时钟转换、单调性、同步误差和跨车映射；不能只以同名帧推定同步 |
| 消息可用性 | 若有实测通信结果，需接收时间/延迟日志及时间域；若没有，需按既有合同明确模拟可用性而非实测延迟 | 源采集时间与消息到达时间分开，deadline 前可用性可复现，不将模拟日志改称实测 |
| 发布检测器 | `late_fusion.zip` 中 `net_epoch60.pth` 对应的训练版本、逐 split 清单、配置、seed、epoch 与 checkpoint 选择日志 | 权重 SHA-256 `9221830d15badc39196164575d49f08dea05e02cea59ef387ed506de919e3fc9` 绑定；证明训练/选择范围，不由推断用 validation_dir 倒推训练过程 |
| 重叠片段 | 作者对实际发布版本 train/test 重复片段及已修订版本的说明 | 对照本次 294 份 PCD 内容重复证据；保持用户要求的协议，不自动更改划分或声明独立性 |
| 公开基线 | CoTrack 完整论文/补充材料与配置；其他缺失算法的官方代码/权重或足够完整的复现资料 | 核验方法身份、许可、版本、输入特征、训练 split 和指标定义，不用同名无关项目替代 |

全部资料取得后先上传 ClearML，保留原字节、来源 URL、取得日期与 SHA-256，再运行准入检查；缺任何必需映射时不生成正式训练成功回执。
